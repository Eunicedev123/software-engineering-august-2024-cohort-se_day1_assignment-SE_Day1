List and briefly explain the phases of the Software Development Life Cycle.
Planning

This phase involves defining project goals, feasibility analysis, resource allocation, and risk assessment.
It ensures the project aligns with business needs and technical requirements.
Requirements Analysis

Developers gather and document functional and non-functional requirements from stakeholders.
Techniques like interviews, surveys, and user stories help in understanding user needs.
Design

Architects and developers create system architecture, database design, and UI/UX layouts based on requirements.
It includes high-level design (HLD) for system structure and low-level design (LLD) for detailed implementation.
Implementation (Coding)

Developers write the actual code using programming languages, frameworks, and tools.
They follow coding standards, best practices, and version control systems like Git.
Testing

The software undergoes rigorous testing to identify and fix bugs.
Types of testing include unit testing, integration testing, system testing, and user acceptance testing (UAT).
Deployment

The tested software is released into a production environment or distributed to users.
It can be deployed in phases, continuous integration (CI/CD), or as a full release.
Maintenance & Support

After deployment, the software is monitored for performance, security, and user feedback.
Updates, bug fixes, and new features are added as needed to improve functionality

Explain the different types of testing (unit, integration, system, and acceptance) and their importance in software quality assurance.
 Unit Testing 
Definition:
Tests individual components or functions of a software application in isolation.
Typically written and executed by developers.
 Integration Testing 
Definition:
Tests the interaction between multiple units/modules to ensure they work together correctly.
Focuses on data flow between components.
System Testing 
Definition:
Tests the entire system as a whole to ensure that it meets the specified requirements.
Conducted in an environment similar to production.
 Acceptance Testing 
Definition:
Evaluates whether the software meets business requirements and is ready for deployment.
Often performed by end-users or clients.

Define prompt engineering and discuss its importance in interacting with AI models.
Prompt engineering is the practice of designing and optimizing input prompts to achieve the best possible responses from AI models like ChatGPT. It involves structuring queries in a way that guides the model to generate accurate, relevant, and high-quality outputs.
Importance
 Enhances Response Accuracy – Well-crafted prompts reduce ambiguity and improve relevance.
 Optimizes Efficiency – Helps AI generate concise and useful responses quickly.
 Enables Customization – Users can guide AI models to adopt specific tones, formats, or styles.
 Improves AI Reliability – Prevents biased, misleading, or incomplete answers.
 Boosts Productivity – Helps businesses and developers automate tasks more effectively.
 


Provide an example of a vague prompt and then improve it by making it clear, specific, and concise. Explain why the improved prompt is more effective.
Vague Prompt:
 "Tell me about food."
 Why it's ineffective?
Too broad – Food includes cuisines, nutrition, recipes, history, and more.
Lacks direction – Does the user want health benefits, cultural significance, or cooking tips?
No format guidance – Should the response be a list, paragraph, or comparison?
Improved Prompt:
 "Describe three traditional Italian dishes, their key ingredients, and how they are commonly prepared."
Why it's more effective?
 Specific Topic – Focuses on Italian cuisine rather than all food.
 Clear Scope – Requests three dishes instead of a general discussion.
 Detailed Requirements – Asks for ingredients and preparation methods, ensuring a well-structured response.
